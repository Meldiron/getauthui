---
title: <authui-config>
description: Declarative configuration element. Invisible; configures the global store from attributes.
---

```html
<authui-config
  endpoint="https://cloud.appwrite.io/v1"
  project="YOUR_PROJECT_ID"
  methods="email-password magic-url oauth:google"
  name="Acme"
  logo="/logo.svg"
  theme="auto"
  radius="lg"
  primary="#fd366e"
  success-url="/dashboard"
  terms-url="/terms"
  privacy-url="/privacy"
></authui-config>
```

The element renders nothing. Changing any attribute reconfigures the store. All attributes are documented in [Configuration](/docs/configuration); the JavaScript `strings` and `oauthScopes` options have no attribute equivalent, use `AuthUI.init()` for those.

`AuthUI.init()` and `<authui-config>` can be mixed: the last one to run wins.

## Misconfiguration

Auth UI checks the connection on startup:

- **Endpoint must end with `/v1`.** Without it Appwrite returns an HTML 404 page. Auth UI warns in the console and shows a developer-facing banner instead of a working-looking form.
- **Wrong project ID or unregistered hostname.** The first `account.get()` returns `project_not_found` or `general_unknown_origin`. Auth UI emits an `error` event, logs a console warning, and shows the same banner on `<authui-sign-in>`.
- **Missing `endpoint` or `project` on `<authui-config>`.** The element no longer leaves the UI stuck on a loading spinner. It reports the gap and `<authui-sign-in>` shows how to finish the setup.
